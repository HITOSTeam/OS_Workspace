# AF_UNIX pathname socket 的 VFS 对象化

## 1. 范围与结论

本批将 AF_UNIX pathname socket 从“规范化绝对路径字符串 + ext4 普通文件占位 +
全局路径表”迁移到统一 VFS：

- `bind()` 通过进程 `FsStruct` 和 `PathWalker` 查找 parent，在目标文件系统中创建
  真实 `VfsNodeKind::Socket`；ext4、TmpFs、bind mount 和相对 cwd 使用同一入口。
- pathname 注册表以 `(filesystem_id, node_id)` 为键，而不是以路径拼写为键；
  rename、hard link 和 bind-mount alias 因而指向同一 endpoint，unlink 后在同名
  路径创建的新 inode 则是独立 endpoint。
- socket 保存 `PinnedPath`，使绑定对象及其 mount 在 socket 生命周期内保持有效；
  close 只注销 endpoint，不自动 unlink 文件系统节点。
- datagram `connect()` 保存已经解析出的 peer，而不是每次 `send()` 重新查同名路径；
  unlink/rebind 不会悄悄把已连接 client 重定向到新 socket。
- abstract namespace 继续按 network namespace 隔离，但与 pathname 注册统一使用
  条件注销和原子发布规则。

最终内核提交为 `188fe417cf4bb28af6fccb115053e15c7bd9c43d`。RISC-V 与
LoongArch soft-float 静态检查通过；RISC-V 专项 smoke、musl/glibc 聚焦 LTP、
CAgent 10/10（200/200）通过。按要求没有运行 BuildStorm，也没有修改基准镜像。

## 2. 原问题

旧 AF_UNIX pathname 实现绕开了统一 VFS：

1. `parse_unix_bound_addr()` 把相对路径与 `cwd_display()` 拼成绝对字符串；
2. `bind()` 用 `find_path_in_roots()` 直接查 ext4 parent；
3. `create_file()` 创建的是普通文件，而不是真实 socket node；
4. `BTreeMap<String, Weak<File>>` 以路径文字查 endpoint；
5. `connect()` 和 `sendto()` 不重新经过 mount graph、chroot root、cwd/dirfd 对象和
   mount-local permission；
6. socket 自身没有保存 mount+dentry 引用。

因此旧实现只能让“同一规范化字符串”命中：rename 后连接失败，hard link 和
bind-mount alias 无法共享 endpoint，unlink/rebind 可能错误重定向，TmpFs/任意
挂载点无法可靠 bind，`stat` 看不到 `S_IFSOCK`，只读 mount 和 mount pin 语义也不
可信。这不是多补几个路径前缀能解决的问题，根因是 endpoint 身份选错了层次。

| `unix_sock.bindlock` | 同一 socket 的并发 bind 串行，不能在 spin lock 中做 pathname I/O | 每 socket `KernelMutex<()> bind_lock` |
| `unix_dgram_connect()` | 保存取得引用的 peer socket；以后发送不按 pathname 重新选择对象 | 保存解析时 peer 的 `Weak<File>` 和 route identity |

本地实现提取的是这些身份、锁序和生命周期原则，没有逐行复制 Linux 的全套
hash bucket、LSM/security hooks、RCU、socket refcount 和 dcache 快路径。

## 4. 实现设计

### 4.1 pathname 与 abstract route 分层

pathname 的输入字符串只用于 `getsockname`/proc 展示及发起 lookup，不再作为
endpoint key。解析后的 key 为：

```text
UnixSocketNodeKey {
    filesystem_id,
    node_id,
}
```

node ID 只在一个 filesystem instance 内唯一，因此必须同时带 filesystem ID。
abstract address 没有 VFS node，仍使用 `(net_namespace_id, name_bytes)`。

### 4.2 bind 的 prepare/create/publish

pathname bind 采用以下事务边界：

```text
每 socket bind_lock
  │
  ├─ resolve parent through FsStruct + mount graph
  ├─ 检查 trailing slash、mount readonly、parent 目录和 write/search permission
  ├─ 计算 umask 与 setgid 目录继承的 gid
  ├─ backend mknod(VfsNodeKind::Socket)
  ├─ 设置 owner，失效 parent positive dentry cache
  ├─ 用 create 返回的 node 构造 uncached child VfsPath
  └─ 在 registry lock 下先发布 socket state，再发布 inode-keyed entry
```

新建 child 不通过名字再次 lookup。`VfsPath::created_child()` 直接保留 create 返回的
node，因此并发 rename/unlink 后，socket 仍固定原对象。这个 dentry 不放入 positive
cache；namespace mutation 仍按统一规则失效缓存。

若 owner 设置或注册失败，rollback 会重新 lookup parent/name，并确认当前节点的
filesystem/node identity 仍等于本次 create 的对象，才执行 unlink。这样不会误删
并发 rename/create 放到同一名字的新对象。

注册表 entry 额外带 socket 的 `proc_inode`。drop 只有在 key 仍属于同一 socket 时
才删除，避免过期 socket 清掉后来注册的对象。registry spin lock 不覆盖 VFS lookup、
backend I/O 或可睡眠等待。

### 4.3 connect/sendto 的对象身份

显式 pathname `connect()`/`sendto()` 每次都走 VFS lookup：

- 路径不存在：保留 walker 的 `ENOENT` 等 errno；
- 目标不是 socket node：`ECONNREFUSED`；
- inode write permission 不满足：`EACCES`；
- node 存在但没有活动 endpoint：`ECONNREFUSED`；
- endpoint socket type 不匹配：`EPROTOTYPE`。

rename、hard link 或 bind mount 只是改变到同一 node 的可达路径，因此 registry 命中
同一 socket。unlink 后同名 bind 会创建新 node/key，不会覆盖仍可由 hard link 访问
的旧 endpoint。

connected datagram 保存解析时 peer 的弱引用。普通 `write/send` 使用该对象；显式
`sendto(address)` 才重新解析当前 pathname。peer close 后弱引用失效并返回
`ECONNREFUSED`，不会命中同名重建的 socket。

### 4.4 path pin 与 close

`UnixSocketState.bound_path` 保存 `PinnedPath { mount, dentry, graph owner }`。因此：

- socket node 被 rename/unlink 后仍可由已持有引用安全存活；
- socket 未 close 时，承载它的 TmpFs mount 对普通 `umount` 表现为 busy；
- drop 先使 endpoint 不再可查，再释放 mount pin；
- close 后文件系统 socket node 仍存在，只有显式 unlink 后才能在同名路径重新 bind。

这与 Linux `unix_sock.path` 的对象所有权一致，不再需要隐藏路径或 fd 旁路 mount 表。

## 7. 性能属性

这批首先是对象身份与 ABI 正确性修复，不把 CAgent 单次耗时波动宣称为性能提升。
它删除了 pathname bind 的 ext4 专用查找和显示路径规范化，但每次显式 connect/
sendto 现在会进行真实 VFS lookup 和权限检查；这正是 Linux 可观察语义需要的成本。

注册表仍为小规模 `BTreeMap`，没有复制 Linux 的分桶 hash 和 RCU。若后续 profiling
证明大量 AF_UNIX endpoint lookup 成为热点，可在保持 `(filesystem,node)` 身份和
相同锁序的前提下替换索引结构，不应恢复字符串路径缓存。

## 8. 已知边界

- `sockaddr_un` pathname 仍沿用项目现有的 UTF-8 `String` 限制；Linux 支持任意
  非 NUL byte pathname。修复它需要整个 pathname ABI 改为 byte string，不在本批
  局部绕开 VFS。
- 通用 VFS 尚无 Linux parent inode lock 跨 `mknod + registry publish` 的完整事务；
  当前用 backend 目录锁、per-socket bind mutex、原子 registry publish 和
  identity-checked rollback 保证不误删/误注册。极端并发 rename 仍可能看到短暂
  `ECONNREFUSED`。
- 未实现 Linux 的 `touch_atime()`、LSM/security hook、RCU-walk 和完整 UNIX
  socket dead-peer/refcount 状态机。
- connected dgram 用弱 peer 引用保持“不会重定向”的语义；它没有复制 Linux
  `sock_hold()` 与 peer wake/disconnect 的全部内部生命周期。
- LoongArch 只完成静态检查，本报告没有把 LoongArch QEMU 运行态记为通过。

这些边界没有用固定测试名、伪造输出或隐藏路径模拟；当前支持范围内的 pathname
创建、查找、mount identity、错误码和对象生命周期均走统一 VFS。
