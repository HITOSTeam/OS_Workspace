# VFS shmem、递归 bind 与 mount graph 对象化

## 1. 范围与结论

本批继续将 pathname、匿名 shmem 与 mount 行为收敛到独立的 `os/src/fs/vfs/`
对象层，完成十二组相互关联的修复：

1. `/dev/shm` 和 memfd 共享统一 shmem mmap 身份；memfd 获得真实的内核
   shmem mount path，`/proc/<pid>/fd/<n>` magic link 返回该 `VfsPath`，不再用
   绝对路径字符串模拟。
2. `MS_BIND|MS_REC` 在 `VfsMountNamespace` 中克隆完整 mount subtree；普通
   bind 只克隆根 mount；unbindable 子树按 Linux 语义剪枝；unmount propagation
   改为由父 mount 的传播关系和 covered dentry 决定。
3. 打开文件自身持有 `PinnedPath`，删除 fd table 中平行维护的 `FdMountRef`；
   dup/fork 只共享同一个 file description。补齐可见 mount root 上的 ordered
   overmount stack、lazy detach 后 dirfd/FD、`fstatfs(fd)` 与 TmpFs FIFO 对象身份。
4. 注册文件系统、文件 bind、根 overmount 和现代
   `fsopen/fsconfig/fsmount/open_tree/move_mount` API 只创建或移动真实 mount 对象；
   删除现代 API 的 record-only fallback，以及已经没有写入者的 `file_binds` 状态。
5. `fspick(FSPICK_EMPTY_PATH)` 直接复制 fd 固定的 `VfsPath`；`mount_setattr()`
   正确提交 propagation 和 Linux 枚举式 atime 属性，使 util-linux 2.41 的
   `--make-private/--move/remount` 不再出现“返回成功但 graph 未改变”或假 `EINVAL`。
6. `/proc/filesystems` 直接枚举 `VfsFileSystemRegistry`，由 factory 的
   `requires_device()` 生成 `nodev` 列；同时删除 `AtPath::PseudoAbs`、
   `ClassifiedAbsPath`、record-only unmount helper 等已失去调用者的过渡状态。
7. `stat/newfstatat/getdents/chdir/fchdir` 的已迁移路径只消费 `VfsPath` 或打开
   file description 固定的对象；不再根据 inode 的显示路径调用
   `open_pseudo(path)`，proc magic link 也不再展开成绝对字符串后二次解析。
8. fanotify 的 inode、mount 和 filesystem mark 分别以 node、mount 和 filesystem
   对象身份为键；事件队列携带目标 `VfsPath`，事件 fd 固定同一对象。exec、旧
   ext4 symlink fallback 和只读挂载根查询也不再调用 mount-source 字符串翻译。
9. 在调用者归零并获得明确授权后，删除中央 `open_pseudo(path)`、mount-source
   canonicalizer/translator、mounted-proc 字符串 helpers 和 proc magic-link
   字符串展开链；pathname 语义只剩对象 walker，source 字符串仅用于设备选择和
   mountinfo 展示。
10. 将 `MS_RDONLY/MS_NODEV/MS_NOEXEC/MS_NOSYMFOLLOW` 从展示路径查询收口为
    `VfsMountFlags`；已存在目标读取解析所得 mount，create 类操作读取 parent
    mount，bind siblings 各自持有独立 flags。link/rename 和挂载点删除也直接比较
    mount identity，不再比较规范化绝对路径字符串。
11. 接入 `openat2(2)` 并把 `RESOLVE_BENEATH/IN_ROOT/NO_XDEV/NO_MAGICLINKS/
    NO_SYMLINKS` 映射到同一个逐分量 walker；严格校验可扩展 `open_how`、flags、
    mode 和精确 errno，不再为 scoped lookup 另建字符串 resolver。
12. cgroup2 的挂载与 `CLONE_INTO_CGROUP` 只认打开目录的 `VfsPath/VfsNode` 稳定
    身份；删除 registry 的 mount-target path map 和 legacy pseudo open。顺带修复
    进程退出延迟析构使已关闭 `f_path` 在 `waitpid()` 后短暂阻塞 `umount` 的问题。

最终 RISC-V 运行态聚焦回归、5 次 cgroup 重复回归和 CAgent 10/10 全部通过，
RISC-V 与 LoongArch softfloat 静态构建通过。按用户要求没有运行 BuildStorm，
也没有修改 14 GiB 基准镜像。

## 2. Linux 设计对照

### 2.1 shmem 与 proc fd magic link

- `exampleOs/linux/mm/memfd.c:471`：`memfd_create()` 通过
  `shmem_file_setup()` 创建文件，而不是建立某个用户可见路径下的普通文件。
- `exampleOs/linux/mm/shmem.c:5782-5848`：shmem 文件位于内部 tmpfs mount，文件
  可在目录项不可见时继续由打开引用存活。
- `exampleOs/linux/fs/proc/fd.c:174-184`：`proc_fd_link()` 直接返回打开文件的
  `f_path` 并增加 path 引用；它不是把展示字符串重新当成绝对路径解析。

对应实现采用内部 `KernelFileSystemKind::Shmem` mount，并让 proc fd 节点返回
带真实 `VfsPath` 和独立展示名的 magic link。VMA 的通用身份从 `memfd_id`
改为 `shmem_id`，因此 memfd 与 TmpFs 都能复用 shared mmap、fork 可见性和
open-unlinked 生命周期机制；只有 `F_SEAL_*` 仍保持 memfd 专属。

### 2.2 bind/rbind

- `exampleOs/linux/fs/namespace.c:2978-2995`：普通 bind 调用 `clone_mnt()`，只有
  recursive bind 调用 `copy_tree()`。
- `exampleOs/linux/fs/namespace.c:2162-2210`：`copy_tree()` 为根和每个子挂载创建
  新 mount 身份，复用 dentry/superblock，并跳过 unbindable 子树。
- `exampleOs/linux/fs/pnode.c:413-441`：unmount 是否传播由
  `parent = mnt->mnt_parent` 及其 propagation domain 决定，再在对应父 mount 上
  查找同一 mountpoint 的 child。
- `exampleOs/linux/fs/pnode.c:646-680` 与
  `Documentation/filesystems/propagate_umount.txt`：传播卸载先收集候选，再检查
  busy/子挂载约束，不能因为待卸载 child 自身属于某个 peer group 就删除全部
  bind peers。

### 2.3 file description、path pin 与 FIFO

- `exampleOs/linux/include/linux/fs.h:1228-1291`：`struct file` 自身包含
  `f_path`、`f_op`、flags 和 position；mount/dentry 引用不在 fd table 中另建一列。
- `exampleOs/linux/fs/file_table.c:355-398,486-529`：`file_init_path()` 把
  `struct path` 安装到 file，最后一次 `__fput()` 才释放 dentry 与 mount 引用。
- `exampleOs/linux/fs/file.c:383-467,1292-1339`：fork 的 `dup_fd()` 和 dup2
  复制/共享 `struct file *`；它们不按 fd 复制独立的 mount reference。
- `exampleOs/linux/fs/pipe.c:1219-1251`：named FIFO 的 pipe state 挂在 inode
  对象上。同一个文件系统对象内的硬链接应共享 FIFO，而不同 superblock 上恰好
  相同的 inode number 不应串线。

对应实现让对象文件及 legacy ext4 adapter 都从 `File::object_path()` 暴露真实
`PinnedPath`。fd table 只保存 `Arc<dyn File>` 与 fd flags；dup、fork、close 和
`fstatfs` 都以 file 自身的 path 为唯一对象身份。TmpFs FIFO 的运行时 key 从裸
`i_ino` 改为 `(filesystem_id, node_id)`。

### 2.4 root overmount 与现代 mount API

- `exampleOs/linux/fs/namespace.c:3191-3242`：不带 `OPEN_TREE_CLONE` 的
  `open_tree()` 返回持有真实 `struct path` 的 O_PATH file；带 clone 时才调用
  `open_detached_copy()` 生成匿名 mount tree。
- `exampleOs/linux/fs/namespace.c:3632-3718,4553-4646`：`move_mount()` 从 fd 的
  `f_path` 或 pathname 取得源 mount，验证源确实是 mount root，再把同一个 mount
  tree 接到目标；`fsopen()+fsmount()` 与 `open_tree(CLONE)` 也走同一个 attachment
  边界。
- `exampleOs/linux/fs/namespace.c:2570-2660`：新 mount tree 的构造与发布分离，
  namespace graph 才是 mount 关系的权威；mountinfo 字符串不是路径解析输入。

对应实现让绝对 lookup 的起点先进入 root mount stack，而 cwd/dirfd 保留其原
`VfsPath`。因此根 overmount 会遮蔽旧根，但 overmount 前打开的 root dirfd 仍可
访问旧 ext4。现代 mount fd 分为 filesystem、detached bind clone 和 live path
三种对象；live path 额外持有 `PinnedPath`，可用于 `fstatfs(fd)` 和 busy 判断。

### 2.5 fspick、mount_setattr 与 filesystem registry

- `exampleOs/linux/fs/fsopen.c:163-207`：`fspick()` 通过 `filename_lookup()` 得到
  `struct path`，仅接受 mount root；`FSPICK_EMPTY_PATH` 由 dirfd 的打开对象取得
  path，而不是把 fd 的显示字符串重新解析。
- `exampleOs/linux/fs/namespace.c:4906-4985`：`mount_setattr()` 在准备成功后同时
  提交 mount flags 与 propagation；propagation 不是普通 attribute bitmap。
- `exampleOs/linux/fs/namespace.c:5048-5098`：atime 属性是枚举。切换模式必须在
  `attr_clr` 中完整给出 `MOUNT_ATTR__ATIME`，再在 `attr_set` 中选择 relatime、
  noatime 或 strictatime。
- `exampleOs/linux/fs/filesystems.c:306-379`：`/proc/filesystems` 从已注册的
  `file_system_type` 生成；没有 `FS_REQUIRES_DEV` 的类型显示 `nodev`。

对应实现沿用这些用户可观察语义，但保持最小边界：live mount fd 上的属性和
传播变更提交到现有 mount graph；尚未附着的匿名 mount 暂不支持 propagation，
明确返回 `EOPNOTSUPP`，不会再返回没有实际效果的成功。

### 2.6 cwd、目录迭代与统一 getattr

- `exampleOs/linux/fs/open.c:550-608`：`chdir()` 先解析得到 `struct path`，
  `fchdir()` 直接使用 `fd_file(f)->f_path`，两者最终都把该对象安装到
  `fs_struct`，不会从 fd 的显示路径重新 lookup。
- `exampleOs/linux/fs/fs_struct.c:16-45`：`set_fs_root()` 与 `set_fs_pwd()` 持有
  mount+dentry 引用，并在替换后释放旧引用。
- `exampleOs/linux/fs/readdir.c:334-405`：`getdents64()` 对已经打开的
  `struct file` 调用 `iterate_dir()`，目录位置保存在同一 file description 中。
- `exampleOs/linux/fs/namei.c` 的 `nd_jump_link()`：proc magic link 把 nameidata
  直接跳转到已固定的 `struct path`，不是先生成绝对字符串。
- `exampleOs/linux/fs/stat.c:169-281`：pathname `stat` 与 fd `stat` 最终都对
  `struct path` 调用 `vfs_getattr()`；同一 inode/superblock 的 `st_dev`、`st_ino`
  不能因入口不同而改变。

### 2.7 fanotify mark 的对象作用域

- `exampleOs/linux/fs/notify/fanotify/fanotify_user.c:1888-2052`：
  `do_fanotify_mark()` 在 lookup 后按 flag 选择真实对象；`FAN_MARK_INODE` 对 inode，
  `FAN_MARK_MOUNT` 对 `vfsmount`，`FAN_MARK_FILESYSTEM` 对 superblock 建 mark。
- 同一实现对 `FAN_MARK_FLUSH` 先按 mark 类型清空 group，不要求为了 flush 解析一个
  pathname；事件对象也不是用挂载 source 或显示路径字符串比较。

对应实现采用最小 REF-walk 模型：inode key 由 filesystem/node ID 组成，mount key
是 mount ID，filesystem key 是 filesystem ID。它不复制 Linux 的 fsnotify mark
connector、RCU 和 SRCU 生命周期实现，但保留当前 ABI 可观察的作用域与对象身份。

### 2.8 mount-local flags 与跨挂载修改

- `exampleOs/linux/include/linux/mount.h:25-52`：readonly、nodev、noexec 和
  nosymfollow 都是 `vfsmount` 的 flags，不是 pathname 前缀属性。
- `exampleOs/linux/fs/namei.c:2037-2042`：walker 在实际准备跟随 symlink 时读取
  `link->mnt->mnt_flags & MNT_NOSYMFOLLOW` 并返回 `ELOOP`；nofollow/readlink 不会
  因此失去读取 link 自身的能力。
- `exampleOs/linux/fs/namei.c:4230-4270` 与 `fs/exec.c:116-123`：设备打开和执行
  分别从解析出的 `struct path` 读取 `MNT_NODEV`、`MNT_NOEXEC`。
- `exampleOs/linux/fs/namespace.c:350-364`：mount readonly 与 superblock readonly
  是两个层次；同一 superblock 的一个 bind 可以只读，而另一个仍可写。
- `exampleOs/linux/fs/namei.c:5841-5857,6135-6150`：link 和 rename 在 VFS 层比较
  old/new `path.mnt`，不同 mount identity 返回 `EXDEV`，即使两者共享同一 inode
  或 superblock。

本项目没有复制 Linux 的 writer freeze/barrier 和完整 superblock write-hold
协议；当前最小实现把 mount-local 可观察语义放到 `VfsPath.mount()`，并用
`PinnedPath` 使已打开对象持续引用解析时的 mount identity。

### 2.9 openat2、cgroup fd 身份与退出时 path 释放

- `exampleOs/linux/include/uapi/linux/openat2.h` 与
  `exampleOs/linux/fs/open.c:1136-1417`：`openat2` 严格拒绝未知 flags/resolve，
  `mode` 只能用于 create-like open；`open_how` 小于 v0 返回 `EINVAL`，超过一页或
  非零扩展字段返回 `E2BIG`。
- `exampleOs/linux/include/linux/namei.h:26-45` 与
  `exampleOs/linux/fs/namei.c:1115-1190,2025-2050,2670-2735`：scoped lookup、
  mount crossing、普通 symlink 和 proc magic link 都是同一 nameidata walk 的
  flags；`LOOKUP_CACHED` 没有 RCU/cached-only 路径时返回 `EAGAIN`。
- `exampleOs/linux/kernel/cgroup/cgroup.c:6756-6900,7325-7355`：
  `CLONE_INTO_CGROUP` 从 cgroup2 目录 fd 取得 cgroup 对象并持有稳定引用，而不是
  从 fd 的显示路径重新查找挂载点。
- `exampleOs/linux/kernel/exit.c:985-1015` 与
  `exampleOs/linux/fs/file.c:490-535`：`exit_files()`/`exit_fs()` 位于退出通知前；
  `close_files()` 释放每个 `struct file`，所以已关闭的 `f_path` 不会在父进程观察
  zombie 后继续造成虚假的 mount busy。

本项目保留锁保护的 REF-walk，不复制 Linux 的 RCU-walk。由于目前没有可证明
“全程只命中缓存”的 RCU/dcache 快路径，`RESOLVE_CACHED` 保守返回 `EAGAIN`；这比
执行后伪称 cached-only 成功更符合 ABI。

## 3. 实现

### 3.1 递归 mount tree 克隆

`os/src/fs/vfs/mount.rs` 新增 `VfsMountNamespace::bind_recursive()`：

- 先获取源 namespace 的 mount-edge 快照；
- 根 bind mount 共享源 filesystem 与 subroot dentry，但获得新 mount ID；
- 按源 `(parent_mount_id, dentry_id)` 关系复制嵌套 mount，保留 stack 顺序；
- 每个子 mount 获得独立 flags、pin、parent relation 和 mount ID；
- unbindable child 会连同其子树一起剪枝，unbindable 根返回 `EINVAL`；
- 所有新 edge 在准备完成后，用目标 graph 的一次写锁发布，后端 lookup/I/O 不在
  graph 写锁内执行。

`mount(2)` 的对象路径现在对 `MS_BIND|MS_REC` 直接调用该接口，不再因为
recursive flag 回退到 legacy resolver。兼容 `MountRecord` 只负责 mountinfo/proc
展示：recursive child 继续标记 `object_vfs=true`，普通 bind 不再伪造 graph 中
不存在的 child records。

### 3.2 unmount propagation 根因与修复

第一次运行中，rbind 本身成功，目标的 root/child/nested 三个 mount 也都可见；
但卸载源 child 后，目标 child 的数据意外消失，而 `/proc/mounts` 仍保留目标
记录。

根因是旧对象实现按“待卸载 child 的 peer group”枚举 detach 目标。默认根是
shared，因此源 child 和 rbind 克隆 child 可成为 peers；但它们的父 mount 位于
不同 propagation groups。Linux 在这种情况下不会把两者作为同一个 unmount
事件移除。

修复后：

- 从待卸载 mount 的 relation 取得 parent 与 covered dentry；
- 仅当 parent 为 shared 时，枚举接收该 parent 事件的 peer/slave parents；
- 在每个候选 parent 的同一相对 dentry 上取得 top child；
- 先对全部候选执行 busy/pin/child 检查，再执行 detach；
- graph 返回实际 detached 的 `(namespace_id, visible_path)`，兼容记录直接按该
  结果删除，不再独立猜测传播域。

这样同时修复了错误批量 detach 和 `/proc/mounts` 陈旧记录。

### 3.3 单元测试源码

在 `os/src/fs/vfs/mod.rs` 增加：

- `recursive_bind_clones_nested_mount_tree`：新 mount ID、共享 filesystem、源和
  克隆独立、父 mount busy、叶到根卸载；
- `unmount_propagation_uses_parent_peer_group`：child mounts 属于同一 peer group，
  但父 mounts 为无关 private trees 时，卸载一侧不得删除另一侧。
- `overmount_through_visible_root_extends_existing_stack`：用户通过当前可见的低层
  mount root 再次 mount 时，新 mount 必须追加到原 covered dentry 的有序 stack；
  卸载顶层后重新露出低层。

当前内核 crate 没有可在宿主机直接执行的 `no_std` 单测 runner；本批通过双架构
编译和 guest 内直接 syscall 回归覆盖这些路径，没有把“新增测试源码”写成
“宿主单测已运行”。

### 3.4 file-owned path 与 ordered overmount

`os/src/task/files_struct.rs` 删除 `fd_mounts`、`FdMountRef` 及所有配套安装、替换
和 clone API。`FileDescription` 现在由具体 file 对象持有 `PinnedPath`；旧 ext4
`OSInode` 直接暴露已有 `vfs_path`，需要保留既有 file operations/downcast 的
legacy endpoint 则由 `PathPinnedFile` 适配。该 adapter 的 `as_any()` 委托给
backing file，因此 ioctl、pipe/FIFO 与 inode 类型判断不会被 wrapper 破坏。

`mount_is_busy()` 对对象 mount 比较准确 mount ID，而不是逻辑路径字符串：

- 旧 dirfd 或 lazy-detached FD 即使与新 mount 使用相同显示路径，也只 pin 原对象；
- dup/fork 共享同一个 file description，自然共享同一个 path pin；
- 普通 umount 检查打开对象，lazy umount 只从 namespace graph 脱离。

用户态再次 mount 时 resolver 会先进入当前 top mount。新增 `stacking_target()`
仅在参数恰好是仍附着、仍为 top 的 mount root 时还原其 parent/covered dentry，
将新 mount 追加到同一 edge 的 stack；旧 covered dirfd、detached mount 或普通
子目录不会被错误折回。与此同时删除了“同 source/type/target 即 EBUSY”的通用
检查，因为每次 `tmpfs` mount 都是独立实例，Linux 允许在同一点 overmount。

### 3.5 graph-only mount 创建与现代 API

`mount(2)` 对 ext4、tmpfs、procfs、sysfs、devtmpfs、cgroup/cgroup2 以及 bind
不再回退到只追加 `MountRecord` 的路径。目标或源不能解析为 `VfsPath` 时返回
`EOPNOTSUPP`，而不是制造一个 graph 中不存在的挂载。`MountRecord` 目前仅保留
source/type/flags 和传播展示数据，供 `/proc/mounts` 兼容输出使用。

现代 API 同样只接受注册的 `VfsFileSystem`：

- `fsconfig(FSCONFIG_CMD_CREATE)` 必须实际创建 filesystem object；
- `fsmount()` 保存该 filesystem，`move_mount()` 才将它一次性 graft 到 graph；
- `open_tree(OPEN_TREE_CLONE)` 保存 detached bind source，attach 时产生新 mount ID；
- 非 clone `open_tree()` 保存 live `VfsPath` 与 `PinnedPath`，`move_mount()` 移动原
  mount，重复使用同一 fd 仍跟随该 mount identity；
- 移动到已有可见 mount root 时，目标先还原成 parent/covered dentry，并按 stack
  顺序接入，避免在被挂载 filesystem 的 root 下错误制造子 edge。

同时删除了 `MountNamespaceState::file_binds`、旧 cgroup 的绝对路径 mutation
入口、record-only mount-handle 构造器和 filesystem registry 的过渡性
`contains()` 分支。文件 bind 的身份现在只存在于 `VfsMount::bind_source` 和实际
dentry/node 中；cgroup registry 的 legacy path map 仍暂留给未迁移 helper。

### 3.6 util-linux 现代重配置链路

聚焦运行最初出现一个反直觉现象：`mount --make-private TARGET` 返回 0，但
`/proc/self/mountinfo` 仍显示 `shared:<id>`；随后 `mount --move` 因父 mount 仍为
shared 而被正确拒绝。直接调用 legacy `mount(NULL, target, NULL, MS_PRIVATE, NULL)`
却会生效。打开 util-linux 调试后确认，2.41 已使用
`open_tree()+mount_setattr()` 完成 propagation 变更。

根因和修复分为四层：

- 旧 `mount_setattr()` 只缓存 `attr_set/attr_clr`，忽略独立的
  `mount_attr.propagation` 后仍返回成功。现在验证四种互斥 `MS_*` propagation
  值，并通过 graph 的统一传播事务提交；`AT_RECURSIVE` 传递为递归传播。
- util-linux remount 会清除完整 atime mask。旧代码把 atime 当普通位图并拒绝
  set/clear 交集；现在按 Linux 的 `MOUNT_ATTR__ATIME` 枚举规则验证，先 clear 再
  set，`remount,ro` 与 `remount,rw` 均作用于真实 mount flags。
- 旧 `fspick()` 先调用 `translate_mount_abs()`，会把 tmpfs 的展示 source
  `"tmpfs"` 当作磁盘路径并得到 `ENOENT`。现在从解析所得 `VfsPath` 的 mount
  直接取得 filesystem type、source 和 flags；empty-path 则复制 fd 已 pin 的
  path，并检查 dentry 确实是 mount root。
- `/proc/filesystems` 新增动态 proc node，其内容由同一个 registry 生成。ext4
  factory 标记 `requires_device=true`，tmpfs/proc/sysfs/devtmpfs/cgroup 均显示
  `nodev`，因此 mount 创建和用户态能力发现不再维护两份类型表。

收尾审计还删除了不再参与 graph 事务的 record-only unmount helper，并把
`stacking_target()` 中 relation read guard 的作用域收紧到复制 parent/covered
对象为止，保证读取 namespace graph 前不继续持有 relation 锁。

### 3.7 pathname 对象身份与 ext4 getattr 收口

本批继续迁移 `path_utils.rs`、`ctl.rs`、`dir.rs`、`stat.rs` 与
`stat_utils.rs`：

- lookup 从进程 `FsStruct` 的 root/cwd 或 dirfd 的 `VfsPath` 起步；绝对路径不再
  先做 proc magic string expansion 或 mount-source translation；
- `chdir()` 安装 walker 返回的对象，`fchdir()` 优先安装打开文件自身的
  `object_path()`；仅对尚无对象 path 的 legacy descriptor 保留 ext4 fallback；
- `getdents64()` 删除“从 `OSInode` 的逻辑路径再次 `open_pseudo()`”的分支，
  因此 overmount 前打开的目录 fd 始终迭代原 inode；
- `newfstatat/statx` 直接统计 walker 返回的节点；`lstat` 保留 proc symlink inode，
  follow 模式则消费 magic link 返回的目标 `VfsPath`；
- syscall 层已经没有 `open_pseudo(path)` 或 `canonical_pseudo_abs()` 调用者；中央
  legacy 定义暂留，待 fanotify/exec 等剩余路径完成迁移后单独删除。

第一次聚焦运行中，proc fd 的目标 inode、mode 和 size 正确，但 pathname
`stat()` 报告 `st_dev=1`，同一文件的 `fstat()` 报告由内部 filesystem ID 产生的
设备号。根因是 ext4 pathname 走 legacy inode snapshot，而 file-owned
`VfsPath` 走通用 `kstat_from_vfs_path()`。修复把 ext4 节点识别和 snapshot 统计
集中到后者；pathname、fd 与 proc magic-link target 现在共享同一 getattr 入口，
也保留 pending write 的 visible-size 语义。

### 3.8 fanotify 与剩余 mount-source 翻译调用迁移

`os/src/fs/fanotify.rs` 将 `FanotifyMark` 的字符串路径/source 目标替换为三类对象
目标：

- inode mark 比较 `(filesystem_id, node_id)`，同一 inode 的硬链接保持同一 mark；
- mount mark 比较 mount ID，同一 filesystem 的两个 bind mount 不会互相命中；
- filesystem mark 比较 filesystem ID，因此从任一 bind 入口访问都会命中；
- `FAN_EVENT_ON_CHILD` 从事件 dentry 的 parent node 取得父目录对象键；
- 事件队列保存目标 `VfsPath`，读出 event metadata 时创建的 fd 用该 path 固定原
  mount/dentry，不再按显示名 reopen；
- `FAN_MARK_FLUSH` 在 syscall 层按 mark 类型直接清空，不解析空或虚构 pathname。

`open/close/read/write/exec` 通知点统一从打开 file 或 walker 结果传递
`Option<&VfsPath>`。exec 解析从 dirfd/cwd/root 对象开始；旧 ext4 absolute symlink
fallback 重新进入统一 `resolve_at_path()`，只读 mount-root 判断则快照真实 mount
graph 并比较 ext4 device/inode。由此 `translate_mount_abs()` 不再有调用者。

本批没有在持有 mount graph 写锁时执行 filesystem lookup 或 fanotify backend
操作；mark 和事件结构通过 `Arc`/锁保护。仍未引入 Linux fsnotify 的 RCU 快路径，
这与本项目 VFS 的最小 REF-walk 约束一致。

### 3.9 删除零调用的伪路径兼容层

在 `rg` 确认所有语义调用者都已迁移、并获得用户明确删除授权后，本批删除：

- `MountBackend::canonical_root()`、
  `MountNamespaceState::{canonical_pseudo_abs,translate_mount_abs}` 及 syscall wrapper；
- filesystem 聚合层的 `current_pseudo_canonical_abs()`、mounted-proc provider、
  exists/fd/readlink helpers、`open_pseudo(path)` 与 `open_canonical_pseudo()`；
- procfs 的 `resolve_proc_magic_intermediate_abs_path()`、
  `ProcMagicLinkFollowTarget`、字符串目录目标拼接链、已失去调用者的
  `proc_fd_link_file(path)` 与 `is_proc_pseudo_path()`。

保留的代码边界是明确的：`proc_magic_vfs_link()` 继续返回对象 `VfsPath`；
`proc_readlink()` 仅生成用户可见文本；PID namespace provider 仍是 proc VFS node
构造的内部实现。sysfs/devtmpfs 的内部 provider 也仍由各自 VFS node adapter
调用，不再存在 pathname syscall 的中央伪文件系统 dispatcher。

### 3.10 mount flags 对象化

`VfsMountFlags` 新增 readonly、nodev、noexec、nosymfollow 的命名常量和语义
访问器。pathname syscall 按操作对象选择检查点：

- open/truncate/chmod/chown/utimens/xattr/exec 读取目标 `VfsPath.mount()`；
- create/mkdir/symlink/mknod/unlink/rename/link 读取解析后的 parent mount；
- device open 和 executable lookup 分别读取目标 mount 的 nodev/noexec；
- path walker 仅在确实要跟随 text 或 magic symlink 时检查 nosymfollow；
- fd 操作通过 file description 固定的 `PinnedPath` 动态读取 mount flags，因此
  bind remount 后不会退回 open 时缓存的路径字符串状态。

`mount_utils.rs` 中的 `path_is_rofs/nodev/noexec/nosymfollow`、
`path_is_mount_point`、`hardlink_cross_mount` 和 readonly mount-root 字符串 helper
已删除。ext4 与对象后端共用 mount-ID 规则：两个同源 bind 之间的 link/rename
返回 `EXDEV`；删除已被 mount 覆盖的 dentry 返回 `EBUSY`。bind 创建时从源
`VfsPath.mount()` 继承 flags，再叠加本次 bind 的 mount-local flags，不再从
`MountRecord` 反推语义。

### 3.11 scoped openat2 与 cgroup2 对象路由

`open_close.rs` 新增 Linux `open_how` v0 读取和校验，并让 `openat/openat2` 共享
同一 `do_openat()`：

- `BENEATH` 在 `..`、绝对路径、绝对/相对 symlink 逃逸时返回 `EXDEV`；
- `IN_ROOT` 把 dirfd 同时作为起点和临时 root，绝对 symlink 与 `..` 被限制在该 root；
- `NO_XDEV` 同时阻止进入和退出 mount，`NO_SYMLINKS` 只在实际 follow 时返回
  `ELOOP`，因此 `O_PATH|O_NOFOLLOW` 仍能取得 final symlink 自身；
- proc magic link 继续直接返回目标 `VfsPath`，`NO_MAGICLINKS` 在 jump 前拒绝；
- `O_CREAT|O_EXCL` 隐含 final nofollow；空路径仅在 `O_EMPTYPATH` 下解析 fd 对象。

cgroup2 adapter 则反向从打开 fd 的 `object_path()` 下转到 `CgroupVfsNode`，用
`filesystem_id + node_id + namespace_root_ino` 验证目标目录并生成 attach target。
`CgroupFile` 只保存 hierarchy key 和稳定 inode ID；registry 不再保存挂载目标路径，
bind subroot 在原展示挂载卸载后仍由 mount/filesystem `Arc` 保持有效。

首次运行发现最终 bind `umount` 在 `waitpid` 后瞬时返回 `EBUSY`。根因不在 cgroup：
退出路径只发送 fd close notification，却把包含 `PinnedPath` 的 `Arc<File>` 留在
idle 渐进清理表中。`FilesStruct` 现在在最后一个 process owner 退出时立即从表中
摘除所有 `object_path().is_some()` 的引用，并在锁外完成 close/drop；匿名对象仍可
渐进析构，共享 fd table、epoll 或 SCM_RIGHTS 持有的真实引用则自然继续存活。

## 6. 明确边界与下一步

- 没有运行 BuildStorm、unixbench、libcbench 或完整性能套件；这是本批约定边界。
- 没有执行 LoongArch QEMU 运行态，只确认 softfloat 静态构建通过。
- 当前对象 propagation 模型覆盖本项目使用的 direct shared peer/slave 关系，但
  还没有复制 Linux 同时 shared+slave、locked mount trimming 等完整 pnode 状态机。
- `AtPath::PseudoAbs` 和 `ClassifiedAbsPath` 已删除；pathname syscall 已不再调用
  `canonical_pseudo_abs` 或 `open_pseudo(path)`；fanotify、exec、旧 ext4 symlink
  resolver 和只读挂载查询也已不再调用 `translate_mount_abs`。获得明确授权后，
  这些中央 helper、proc 字符串 magic-link resolver 及其私有依赖均已删除；源码
  搜索没有残留命中。
- `FdMountRef`、`fd_mounts` 及其安装/clone/fstatfs fallback 已全部删除；源码
  搜索没有残留命中。
- `file_binds`、现代 mount API 的 record-only fallback 和 record-only unmount
  helper 已删除；所有新挂载事件先修改对象 graph，再同步兼容展示记录。cgroup
  registry 的 legacy mount-target path map、pseudo opener 和 mount path splitter
  也已删除；`CLONE_INTO_CGROUP` 只消费 fd 固定的 VFS 节点身份。
- live mount fd 的 propagation、非递归 mount attributes 已落地；匿名 detached
  mount propagation 与递归普通 attribute 仍明确返回 `EOPNOTSUPP`，尚未实现
  Linux 的 idmapped mount。
- mount-local readonly/nodev/noexec/nosymfollow 已改为读取解析所得
  `VfsPath.mount()`；create 类目标读取 parent mount，旧展示路径 helper 已删除。
- `openat2` 已覆盖当前公开 v0 resolve 语义；本地 `exampleOs/linux` 额外存在尚未
  纳入本项目 ABI 的未来 `OPENAT2_REGULAR` 扩展，本实现将未知高位严格返回
  `EINVAL`。`RESOLVE_CACHED` 在引入可证明的 dcache-only walk 前保守返回 `EAGAIN`。
- 退出 fd 表已经及时释放 pathname pins；独立 `FsStruct` 的 cwd/root 在未被 reap
  的 zombie 上仍值得补一组 mount-busy 专项审计。下一批还应把这一生命周期边界
  与 openat2 LTP/openat2-tools 兼容组纳入聚焦回归。
