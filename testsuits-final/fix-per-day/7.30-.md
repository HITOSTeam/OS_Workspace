# 7-30 系统瓶颈基线与优化顺序

## 问题概述

这份记录不是一次已经完成的修复，而是 7 月 30 日对系统状态的基线判断。当时内核
已经能在精简指令集计算机第五版架构（RISC-V）上使用 8 个处理器核心运行较完整的
用户环境，CAgent 也曾达到 10/10；主要问题已经从“缺少系统调用”转成以下四类结构性
问题：

1. ext4 文件系统被一把全局锁串行化，块设备请求又在提交后持续轮询完成状态；
2. 共享文件映射、文件截断、脏页回写和缓存失效没有形成统一的文件页生命周期；
3. 虚拟文件系统（Virtual File System，VFS）同时存在对象路径和字符串路径两套入口；
4. RISC-V 已有多核调度，LoongArch 当时仍未形成完整的次级处理器启动和跨核地址转换
   缓存失效路径。

这些问题互相放大。例如并行编译会同时触发进程创建、文件缺页和 ext4 目录操作；
如果文件系统、内存管理和调度器各自仍有全局串行点，增加处理器核心并不会得到对应
吞吐，反而会增加锁竞争。

## 如何发现

早期判断来自源码审查和已有测试记录，不是一次 `perf` 性能采样。本目录当时没有为
这份总览单独保存串口日志；可复核结果记录在：

```text
testsuits-final/record.md
user/src/bin/ltp_dependence/record.md
```

当时的关键观察包括：CAgent 最新一轮只有 7/10，`fs-create`、`fs-directory`、
`fs-search` 没有完成；`fsx-linux` 记录为 0/10，并出现读取旧数据；完整 BuildStorm
尚无成功日志。源码上的全局串行点可以用历史提交复核：

```sh
git -C os show 43a786f:src/fs/inode.rs | \
  rg -n 'EXT4_LOCK|with_ext4_lock'
git -C os show 43a786f:src/drivers/block/virtio_blk.rs | \
  rg -n 'Mutex<VirtIOBlk|read_blocks|write_blocks'
git show 53368b5d^:ext4-fs/src/block_cache.rs | \
  rg -n 'BLOCK_CACHE_MANAGER|read_block|sync_all'
rg -n 'open_pseudo|PathWalker|VfsMountNamespace|VfsPath' os/src/fs
```

前两组命令显示 ext4 与块设备调用被粗粒度锁覆盖；第三组显示缓存管理器在读取、同步
路径中持有全局锁；最后一组显示对象化路径与旧字符串分发仍同时存在。因为没有保留
同环境的性能对照，这里只记录“为何应优先处理”，不填写加速百分比。

## 怎么解决

这份基线给出的顺序是先建立可观测性，再分层消除根因：

```text
串口进度、每个核心调用栈、锁等待和块队列状态
    -> ext4 inode/目录锁域与块缓存锁外输入输出
    -> 文件页缓存、截断、写回和映射统一生命周期
    -> 所有路径操作进入 VFS mount+dentry 对象图
    -> LoongArch 次级处理器、跨核中断和地址转换缓存一致性
```

Linux 的对应设计不是“删掉所有锁”，而是把所有权放在正确对象上：inode 的读写信号
量保护单个 inode，`address_space` 管理单个文件的缓存页和映射，`struct file` 持有
打开对象及其路径，块层允许多个请求在途并由中断完成。本项目后续也应按这些对象边界
逐步迁移，不能直接删除 `EXT4_LOCK`，否则只会把性能问题变成元数据损坏。

具体后续记录分别见：

- `7.31-ext4-virtio-concurrency.md`：实际拆锁、缓存状态机和块设备并发；
- `8-3-linux-file-page-cache.md`：统一普通文件私有映射的文件页缓存；
- `8.2-vfs-shmem-rbind.md`：对象化路径和挂载图收口；
- `8-2-loongarch-smp-tlb-lifecycle.md`：LoongArch 多核与地址转换缓存一致性。

## 对比提升

本条没有修改前后的受控性能测试，因此不声明性能提升。它的可核对产出是把后续工作
从“继续补单个 Linux Test Project（LTP）测试”调整为文件系统、内存管理、路径对象
和多核一致性的联合修复，并为后续专题建立了清晰的验收边界。

## 后续优先级

| 优先级 | 问题 | 当时的验收目标 |
| --- | --- | --- |
| 最高 | ext4 与块设备全局串行 | CAgent 文件组稳定完成；并行文件测试有受控对照 |
| 最高 | 文件页一致性 | `fsx-linux` 不再读到旧数据，映射与截断语义稳定 |
| 高 | VFS 双轨路径 | mount、rename、打开文件和命名空间只认对象身份 |
| 高 | LoongArch 多核 | 所有配置核心上线，跨核页表更新有同步确认 |
| 中 | 网络与现代接口 | 在真实测试需要时按对象生命周期逐批补齐 |
